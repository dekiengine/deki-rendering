deki-rendering

Core rendering system with camera and renderer components

Repository: github.com/dekiengine/deki-rendering · Latest release: 0.22.0 · Needs engine 0.22.0+

Install with DekiEditor --packages-add deki-rendering <project>, or from the Package Manager. The engine's own components and C++ API are in the Deki docs.

Shown in the editor as Rendering.

Component reference

CameraComponent

The view: position, how much world it shows, and clear color.

Inspector name: Camera Component · Category: Core · Type: DekiRendering::CameraComponent

Property Type Default Constraints Description
clearColor Color "#314D79FF" Colour the screen is filled with before anything is drawn. What shows wherever nothing covers it.
projection enum "Orthographic" Orthographic, Perspective Orthographic shows a fixed height of world, flat. Perspective shows a field of view in depth, for 3D meshes; sprites still draw flat.
orthoHeight float 15 0.01 to 100000; in m; shown when projection allows How much world the camera shows top to bottom. Every screen scales it to fill its height (the x beside it).
pixelPerfect bool false shown when projection allows For pixel art. Scales by whole numbers only, so every art pixel is the same size on screen, and snaps the camera to the art-pixel grid. Rounds down: the camera shows a little more than its ortho height, and a screen too small for 1x crops.
fieldOfView float 60 10 to 150; shown when projection allows Vertical field of view in degrees. A wider screen sees more at the sides. 60 is a common default; larger looks wider and more distorted at the edges.
nearPlane float 0.1 shown when projection allows Nothing closer than this is drawn. Raising it costs nothing and buys depth precision, so keep it as large as the scene allows.
farPlane float 100 shown when projection allows Nothing further than this is drawn.
clearEveryFrame bool true Clear before each frame. Off, the previous frame stays underneath: faster when a full-screen background covers everything, and occasionally what you want for trails.

Project settings

Rendering settings

Project settings section Rendering (RenderingProjectSettings).

Category: Settings · Type: DekiRendering::RenderingProjectSettings

Property Type Default Constraints Description
frameMode enum "Auto" Auto, WholeFrames, Strips How each frame reaches the screen. Auto (the default) chooses on the device when the game starts: whole frames when the framebuffer fits in internal RAM with room to spare, strips when it does not (a 536x240 screen at 2 bytes a pixel is 257 KB, more than the free internal RAM of an ESP32-S3). Whole frames draws each frame once, in one buffer, and is the faster choice whenever that buffer is in internal RAM. Strips draws the frame a strip of rows at a time into a small buffer in internal RAM and sends each strip while the next is drawn, which is much faster than drawing a whole frame in PSRAM. Both give the same pixels and keep every feature. The boot log and DEKI:STATS say which one a board uses and why. The editor always draws whole frames.
bandRows int32 40 2 to 256 Rows in each strip, when frames are drawn in strips. 40 suits most screens. Taller strips walk the scene fewer times a frame but need more internal RAM: a strip, and two copies of it for sending, of the screen's width times this many rows at 2 bytes a pixel.
redrawChanges bool false Redraw only what changed: each frame compares what every object draws with the last frame and draws and sends only the parts of the screen that differ. A frame where nothing moved costs almost nothing. When most of the screen changes (a scrolling camera, a full-screen animation) that frame is drawn whole as usual. A render pass that cannot say where it draws, or a camera that does not clear, makes every frame whole.

Changelog

0.22.0

Changed

  • The frame buffer and the render strip are counted in the engine's memory figures. They came from Memory::AllocateInternal, which counts nothing, so the largest buffer on a board was missing from every total and from the editor's Memory panel. They now come from Memory::Allocate in the Internal region, as before in internal RAM.
  • minEngine 0.22.0: built against engine 0.22.0. A build of this package from before does not load and is rebuilt.

Fixed

  • A Linux desktop game no longer crashes as it exits. A package's render pass (deki-particles) was detached from a pass list that static destruction had already freed.

0.21.0

Changed

  • minEngine 0.21.0: built against engine 0.21.0. A build of this package from before does not load and is rebuilt.
  • Redraw only what changed (project setting redrawChanges, off by default; DekiRenderSystem::SetRedrawChanges). Before drawing, the renderer compares each object with the last frame: where it lands and what decides its pixels (content and its version, size, pivot, tint, scale, rotation, clip, place in the draw order). Only the parts that differ are cleared, drawn and sent; a frame where nothing moved costs only the comparison. Past 75% of the screen, or when something cannot say what it draws, the frame is drawn whole as before. Whole frames and strips both do it, and a display that alternates buffers gets every change since each was drawn. On a T-Deck Plus the demo's menu went from 7.6 ms render and 3.4 ms send to 2.0 ms and 0.1 ms; a fully animated scene costs what it did. The editor's Play view does it too.
    • DekiRenderer::FindChanges and RenderContext::redraw (Standard2DRenderer implements them). RendererComponent::GetContentVersion: a component whose pixels change in place says so; one that does not counts as changed every frame it draws. RenderPass::ReportsChanges, AddChanges and FinishChanges: a pass that cannot say where it draws makes every frame whole, as does a pass with hooks other than Execute or a camera that does not clear.
    • QuadBlit::SetTargetLimit: a rect every blit stays inside, even with clipping off (ignoreClip), so nothing writes outside the part redrawn.
    • The profiler's Changes entry times the comparison.
    • Packages built against an older deki-rendering must be rebuilt: RendererComponent and RenderPass have new virtual functions.
  • Drawing in strips keeps each object's content with its place in the frame's plan instead of in a map rebuilt every frame.
  • No clear under a full-screen background. A whole frame was cleared to the camera's colour and then drawn over. Standard2DRenderer now clears just before its first draw, and not at all when that draw is opaque and covers the screen: 0.49 ms a frame on a T-Deck Plus. Passes can write anywhere, so the clear comes before any of them runs (an Execute pass only for an object it WantsObject). A renderer takes this on with DekiRenderer::ClearsLazily() and RenderContext::clear.
  • See-through sprite edges draw faster. An untinted sprite with soft edges blended them through the general per-pixel pipeline; it now has its own loop, which also skips each row's transparent run without reading it. Its blits in the demo's meadow take 1.29 ms instead of 1.97 ms on a T-Deck Plus (render 5.9 to 5.1 ms), with the same pixels. Blends onto RGB565 mix red and blue in one word: two multiplies fewer a pixel, the same result.
  • Turned sprites draw faster. A rotated blit visits only the pixels of its box that land inside the sprite, worked out once a row, instead of testing every pixel of the box. An RGB565 or RGB565A8 sprite turned onto an RGB565 frame, tinted or faded, has its own loop (TintRotatedRows in the profiler) instead of the per-pixel pipeline: the demo's spinning gear takes 0.67 ms instead of 0.87 ms on a T-Display S3, with the same pixels. Other rotated blits (a colour key, dithering, flips, other formats) run from flash, so they take no internal RAM.
  • Scaled sprites and particles onto RGB565 find each source pixel with a shift instead of a multiply (TintScaledRows): 5% faster.

Added

  • Fingerprint.h: a 64-bit fingerprint over 32-bit words with 32-bit multiplies only, for telling whether something changed since the last frame. A 32-bit microcontroller has no 64-bit multiply.
  • QuadBlit::Source::stretchWidth / stretchHeight: one column or one row drawn as the whole picture it stands for, placed, scaled, clipped and rotated as that picture would be. A plain opaque one onto RGB565 is filled row by row (StretchRows in the profiler) instead of sampled pixel by pixel. QuadBlit::DrawnWidth / DrawnHeight give the size a source is drawn as.

Removed

  • Dirty-rect tracking (project settings dirtyTileTracking and dirtyTileSize, QuadBlit::MarkDirty, SetDirtyTracking, DekiRenderer::trackDirty, GetLastFrameDirty). redrawChanges does the same job and also skips the drawing. A project's old keys are ignored; turn on redrawChanges instead.
