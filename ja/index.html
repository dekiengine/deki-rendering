deki-rendering

コアのレンダリングパイプライン。カメラ、レンダーシステム、標準 2D レンダラー、QuadBlit、レンダーパス、ソートを提供します。

リポジトリ: github.com/dekiengine/deki-rendering · 最新リリース: 0.20.0 · エンジン 0.20.0 以降が必要

DekiEditor --packages-add deki-rendering <project> か、パッケージマネージャーからインストールします。エンジン自身のコンポーネントと C++ API は Deki のドキュメントにあります。

エディターでは Rendering と表示されます。

CameraComponent

ビューです。位置、ワールドを映す範囲、クリアカラーを決めます。

インスペクターでの名前: カメラコンポーネント · カテゴリ: コア · 型: DekiRendering::CameraComponent

プロパティ 型 デフォルト 制約 説明
clearColor Color "#314D79FF" 何かを描く前に画面を塗りつぶす色です。何も覆っていない場所にはこの色が見えます。
projection enum "Orthographic" Orthographic, Perspective 平行投影はワールドの一定の高さを平面的に映します。透視投影は視野角で奥行きを映す、3D メッシュ向けの方式です。スプライトはどちらでも平面的に描かれます。
orthoHeight float 15 0.01 から 100000。単位 m。projection が許すときに表示 カメラが上から下まで映すワールドの量です。どの画面もこれを高さいっぱいに拡大して表示します (横の x が倍率です)。
pixelPerfect bool false projection が許すときに表示 ピクセルアート向けです。整数倍でのみ拡大するので、アートの 1 ピクセルが画面上ですべて同じ大きさになり、カメラもアートのピクセルグリッドに合わせます。倍率は切り捨てるため、カメラは平行投影の高さより少し広く映し、1 倍に満たない小さな画面では端が切れます。
fieldOfView float 60 10 から 150。projection が許すときに表示 垂直方向の視野角 (度) です。横長の画面ほど左右が広く見えます。60 が一般的な既定値で、大きくするほど広く、端がゆがんで見えます。
nearPlane float 0.1 projection が許すときに表示 これより近いものは描かれません。大きくしても負荷は増えず、深度の精度が上がるので、シーンが許す範囲で大きくしてください。
farPlane float 100 projection が許すときに表示 これより遠いものは描かれません。
clearEveryFrame bool true フレームごとに描く前に画面をクリアします。オフにすると前のフレームが下に残ります。全画面の背景がすべてを覆う場合は速くなり、残像を出したいときにも使えます。

プロジェクト設定

レンダリング 設定

プロジェクト設定のセクション Rendering (RenderingProjectSettings) です。

カテゴリ: 設定 · 型: DekiRendering::RenderingProjectSettings

プロパティ 型 デフォルト 制約 説明
dirtyTileTracking bool false 差分矩形の追跡です。各フレームが描いた矩形を記録し、次のフレームではそこだけをクリアして、変わった部分 (今回と前回のフレームの矩形) だけをディスプレイへ送ります。ほとんど静止したシーンで大きく効き、全体が動くシーンでは管理のコストが少しかかります。部分的な表示ができないディスプレイには、これまでどおりフレーム全体を送ります。
dirtyTileSize int32 32 1 から 256。dirtyTileTracking が許すときに表示 差分矩形の揃え単位 (ピクセル) です。各矩形はこの倍数まで広げられます。大きいほど送る回数が減って 1 回が大きくなり、小さな動きは同じ矩形を使い回します。小さいほど矩形がぴったりになります。
frameMode enum "Auto" Auto, WholeFrames, Strips 各フレームを画面に届ける方法です。Auto (既定) はゲームの開始時にデバイス上で選びます。フレームバッファーが内部 RAM に余裕をもって収まればフレーム全体、収まらなければストリップです (2 バイト/ピクセルで 536x240 の画面は 257 KB で、ESP32-S3 の内部 RAM の空きより大きくなります)。フレーム全体は各フレームを 1 つのバッファーに 1 回で描き、そのバッファーが内部 RAM にあるときはこちらが速くなります。ストリップは内部 RAM の小さなバッファーに数行ずつ描き、次を描いている間に各ストリップを送ります。PSRAM にフレーム全体を描くよりずっと速くなります。どちらも同じピクセルになり、すべての機能が使えます。どちらを使ったかとその理由は、起動ログと DEKI:STATS に表示されます。エディターでは常にフレーム全体で描きます。
bandRows int32 40 2 から 256 フレームをストリップで描くときの、各ストリップの行数です。ほとんどの画面には 40 が合います。ストリップを高くすると 1 フレームでシーンをたどる回数が減りますが、内部 RAM を多く使います (ストリップ 1 つと送信用のコピー 2 つ、それぞれ画面の幅 × この行数 × 2 バイト)。

変更履歴

変更履歴は英語です。

0.20.0

Added

  • Strips along a display's refresh. A display that wants it offers IScanOrderedDisplay (RegisterScanOrderedDisplay): the order its panel refreshes the screen in, rows down or up, or columns left to right or right to left. DekiRenderSystem then cuts strips along it, in that order, and sends each with PresentStrip: the whole strip, what changed in it, and whether it is the frame's first. A strip of columns is as many pixels as bandRows rows would be, in whole eights of columns so the ordered dither's tile stays where the whole frame has it. RenderContext gains viewLeft and viewWidth, the x twins of viewTop and viewHeight, and DrawsInStrips means strips of rows or of columns. Every whole-frame feature works in either: dirty rectangles, a camera that does not clear, screenshots. Deki::IDisplay does not change, so no package is rebuilt for it.
  • Big-endian RGB565 (DEKI_RGB565_BIG_ENDIAN, see Deki::kRGB565BigEndian): DekiPixel::Load565, Store565, ToMemory565, FromMemory565 and FileToMemory565 read and write 565 values in memory's byte order. The blitter, its tint tables and chroma keys, clears and GetPixel use them. Copies of whole pixels are unchanged. The golden tests run in both byte orders and give the same hashes.
  • RenderProfiler times each of QuadBlit's paths (its fast loops and the generic scaled and rotated pipelines): blits, destination pixels and microseconds per frame (AddPath, TakePaths). Entries carry the component's short name, which a stripped build's registry cannot give.

Changed

  • minEngine 0.20.0: built against engine 0.20.0. A build of this package from before does not load and is rebuilt.
  • On the ESP32's Xtensa cores an RGB565 pixel is read and written with one 16-bit access, aligned or not (DekiPixel::LoadU16 and StoreU16). The cores handle unaligned loads and stores in hardware; GCC assumes they fault, so the byte-by-byte read it replaced was four instructions. Other targets use memcpy.

Removed

  • halfWidthFramebuffer and interlaced60hz from the Rendering settings: neither was ever built, though their tooltips described them as if they were. A project that still has them in its settings loads as before; they are left out when it is saved.

0.19.0

Changed

  • minEngine 0.19.0: built against engine 0.19.0, whose component metadata records the package each class is in. A build of this package from before does not load and is rebuilt.

Added

  • Japanese, Simplified Chinese and Korean: editor/lang/ja.json, zh.json and ko.json translate the names, tooltips and enum values this package's components show in the Inspector.
  • The package's editor text goes through the editor's translation (Tr), so it shows in the editor's language. Needs the editor release that adds Localization.h; raise minEngine to it when releasing.
